## 12.10.2026 — видео: съёмка не начиналась («Godot запущен без --fixed-fps»)
Жалоба (скриншоты консоли): `Godot.exe --path . --fixed-fps 30 res://tests/promo_video.tscn` → «перезапуск с
--fixed-fps 30», новое окно → «Godot запущен без --fixed-fps», и тут же «Качество: среднее → низкое (30 к/с)».
- Причина: `_measure_fixed_fps` брала кадры 2–5 сразу после запуска и требовала разброс ≤ 0,5 мс. А первые ≈6 кадров
  MainTimerSync подгоняет шаг под такты физики (60/с): даже с `--fixed-fps 30` шаг 0,025 / 0,033 / 0,042 / 0,029 /
  0,030 / 0,0325, потом ровно 1/30 (модель MainTimerSync на Python). Значит, «нет --fixed-fps» → перезапуск → то же
  → отказ. Что `--fixed-fps` работал, видно по строке автоснижения: 30 к/с (без него было бы ≈60).
- Исправление: шаги меряются до DETECT_SAME = 3 совпадений подряд (не дольше DETECT_MAX_FRAMES = 30 кадров);
  шаг > DETECT_SLOW = 0,09 с — сразу «нет --fixed-fps» (без него с задержкой 120 мс шаг ≈0,117–0,128 по модели).
  Все шаги короткие, но не устоялись — всё равно снимаем, с предупреждением.
- `Quality.set_auto(false)` в начале `_ready`: замер и окно итога больше не снижают и не сохраняют качество игрока
  (так у пользователя в settings.cfg осталось «низкое» — вернуть: F3, затем F4 по кругу).
- check_gd — 0 проблем. Godot здесь нет — не запускалось.
