# Десктоп и Яндекс Игры: требования и решение

Источники (прочитаны 01.10.2026): требования к игре `yandex.ru/dev/games/doc/ru/concepts/requirements`,
разборы пунктов `.../requirements/1/10` и `.../requirements/5/1/1/2`, описание черновика
`.../console/add-new-game/draft`. Требования меняются, поэтому перед отправкой на модерацию (этап 16.6)
перечитать эти страницы.

## 1. Что требует Яндекс

| Пункт | Требование | Что это значит для нас |
|---|---|---|
| Черновик | Платформы: Десктоп, Мобильные (iOS / Android), ТВ. Каталог фильтрует игры по ним | Без галочки «Десктоп» игру не увидят игроки с компьютеров |
| 1.6 | Игра выполняет требования для всех платформ, отмеченных в черновике | Отметили десктоп — проходим все пункты 1.6.2 |
| 1.6.2.1 | Активное поле растягивается по вертикали **или** горизонтали до края доступной области (без стики-баннеров) | Вертикальная колонка во всю высоту формально подходит |
| 1.6.2.2 | Длинная сторона активного поля не более чем вдвое длиннее короткой | 9:16 — это 1,78, подходит |
| 1.6.2.4 | Управление мышью или клавиатурой по умолчанию, **не зависит от раскладки** | Горячие клавиши R / Z / H — по `physical_keycode` (сделано в 13.0, `Desktop.key_pressed`) |
| 1.6.2.6 | Нет сочетаний, занятых системой или другими приложениями | Ctrl+Z — обычное «отменить», вряд ли считается системным; дубль — Backspace |
| 1.6.2.7 | Игровое поле не выделяется, не открывает контекстное меню | ПКМ поворачивает блок: проверить в черновике, что меню браузера не появляется |
| 1.8 | Интерактивные элементы адаптированы под размер экрана и удобны | На 1920×1080 блоки и кнопки сейчас мелковаты |
| 1.10 | Корректный вид при любом размере окна: ничего не обрезано, не наложено, нет полосы прокрутки | Модерация вписывает окно в 16:9, затем ужимает на 20 % по каждой оси; разрешения 1280×1024…3840×2160; масштаб браузера 80–125 % |
| Черновик, «Ориентация» | Для мобильных: портретная, альбомная или любая. В неподдерживаемой ориентации SDK сам показывает заглушку «поверните экран» | Оставляем «Портретная» |
| Черновик, скриншоты | Десктопные — **только альбомные 16:9**, от 1280 до 2560 px, минимум 2 на каждую платформу | Нужны кадры игры в альбомном окне |
| 5.1.1.2 | Геймплей занимает не меньше 70 % скриншота. Отказ, если больше 30 % занято однотонным фоном или градиентом | Сейчас колонна занимает ≈32 % ширины 16:9 — это ровно пример отказа из документации |

Чёрных полос Яндекс прямо не запрещает. Но пустые бока плохо выглядят, мешают скриншотам и
тратят место, которое могло бы уйти на поле.

## 2. Как было до 13.0 (по коду, 01.10)
- `project.godot`: база 720×1280, `stretch/mode = canvas_items`, `aspect = expand`.
  Экспорт: `canvas_resize_policy = 2`, то есть холст заполняет всё окно, чёрных полос нет.
- `Content` в меню и в игре — колонна шириной 720, стоит по центру. `Background`, `WinPanel`,
  `PausePanel` и шторка `Transition` растянуты на весь экран.
- В окне 16:9 (1920×1080) логический экран ≈2276×1280. Колонна занимает ≈32 % ширины, поле
  ≈570×570 экранных px, по бокам градиент с едва заметными квадратами.
- Итог: формально 1.6.2.1, 1.6.2.2 и 1.10, скорее всего, выполнены (проверить в черновике). Но игра
  выглядит как телефон посреди монитора, а десктопный скриншот попадает под отказ по 5.1.1.2.

## 3. Варианты

| | Колонна + оформление боков | Альбомная раскладка (рекомендую) |
|---|---|---|
| Что это | Раскладка прежняя, по бокам крупные глянцевые блоки-декор в стиле A2, лёгкое движение | При широком окне поле слева и крупнее, лоток — столбик из 3 гнёзд справа, кнопки рядом с лотком |
| Поле на 1920×1080 | ≈570 px, как сейчас | ≈850 px (в 1,5 раза больше) |
| Скриншоты 16:9 | Колонна ≈32 % ширины, остальное спасает только декор | Поле + лоток ≈60–70 % ширины, остальное — декор |
| Мышь | Как сейчас | Путь «лоток → поле» короче и горизонтальный |
| Цена | S: только фон | M: две раскладки в `game.gd` и `menu.gd`, переключение по `size_changed` |
| Риск | Модерация скриншотов | Проверка обучения (рука, подписи) в обеих раскладках |

## 4. Решение (подтверждено 01.10, сделано в 13.0 — 02.10)
1. **Две раскладки по соотношению сторон логического экрана.** Если ширина / высота ≥ 1,15 —
   альбомная, иначе портретная. Небольшой гистерезис, чтобы не «дребезжало» при ресайзе.
   5:4 (1280×1024) — это 1,25, альбомная. 16:9, ужатое на 20 % по ширине, — 1,42, тоже альбомная.
2. **Альбомная раскладка игры** (логическая высота 1280):
   - поле — на всю высоту (квадрат до ≈1170×1170 логических px), слева;
   - справа — столбик: пауза | уровень и счёт | рестарт, «Осталось блоков», 3 гнезда лотка
     (`BoxContainer.vertical = true`), под ним «Отмена» и «Подсказка»;
   - бока — только фон стиля. Блоки-декор отклонены 01.10 («выглядят как мусор»), поэтому
     поле и столбик вместе занимают ≈79 % ширины 16:9 (кадр `A3B_desktop.png`, раскладка как у A3).
   Поле само вписывается в `BoardArea` (`board.fit_in`). Рука и подписи обучения берут глобальные
   координаты, поэтому менять нужно только якоря и отступы.
3. **Меню, победа, пауза:** логотип и кнопка «Играть» крупнее по центру, по бокам фон стиля. Карточки
   победы и паузы остаются по центру, они и так на весь экран.
4. **Телефоны:** в черновике «Портретная». В альбомной ориентации у телефона ≈390 css px высоты —
   кнопки стали бы меньше пальца, поэтому пусть SDK показывает «поверните экран». Планшеты позже
   можно перевести на «Любая», если альбомная раскладка на них хороша.
5. **Мелочи для мыши и клавиатуры:** hover у кнопок и блоков лотка, курсор-«рука», горячие
   клавиши по `physical_keycode`, подсказка про ПКМ / R для поворота только на десктопе.
6. **Где в плане:** кадр `A2_desktop` рисуется в этапе 12.3 вместе с A2. Раскладка — пункт 13.0,
   до вертикального среза 13.1: срез смотрим сразу в обеих раскладках. Десктопные скриншоты — 16.5,
   проверка по таблице из раздела 1 — 16.6.

## 5. Как проверить (к 16.6)
- Окно 16:9, затем минус 20 % по ширине и по высоте, затем 5:4 и 21:9 (2560×1080): ничего не
  обрезано и не наложено, раскладка переключается без мигания.
- Масштаб браузера 80 %, 100 %, 125 %: нет полосы прокрутки.
- ПКМ по полю — меню браузера нет. Русская раскладка — R / Z / H работают.
- DevTools, эмуляция телефона в портрете: портретная раскладка как раньше.

## 6. Что сделано в 13.0 (02.10)
- `scripts/game_layout.gd` (`GameLayout`): `pick` — режим с гистерезисом 1,15 / 1,10, `compute` — прямоугольники
  обеих раскладок по `docs/STYLE.md`, раздел 13. Python-двойник — `tools/layout_model.py`, схемы — `docs/layout/`.
- `game.tscn` / `game.gd`: `Content` на весь экран, места узлов ставит `Game.apply_layout()` по `resized`.
  Лоток — `BoxContainer` (`Tray.arrange`: ряд или столбик, гнездо 216×232 / 532×256, блок 0,46 / 0,78).
  Поле — до ×1,35 в портрете и ×2,4 в альбоме (`Board.max_scale`).
- Подписи «ПКМ или R — повернуть блок» нет (убрана 11.10 по решению пользователя): игра целиком управляется левой
  кнопкой мыши, поворот — щелчок по блоку в лотке, как в обучении. ПКМ, колесо и R работают, но не подписаны.
- Клавиши по месту: Z, H, R, пробел, Backspace, Enter (`Desktop.key_pressed`). Enter — «Играть» и «Далее».
- Наведение: ×1,05 и курсор-«рука» у кнопок игры, меню, паузы и победы и у гнёзд с блоком
  (`Desktop.add_hover`). От касаний (эмуляция мыши) и на выключенных кнопках не срабатывает.
- Меню в альбоме пока прежнее (колонна по центру, логическая высота та же 1280). Крупнее логотип и
  «Играть» — в 13.6 вместе с новым видом меню.
- Не проверено в Godot: смотреть по чек-листу в `PROGRESS.md` (раздел «Не проверено в Godot»).
